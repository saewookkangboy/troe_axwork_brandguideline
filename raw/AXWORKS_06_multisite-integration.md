## 1. 현재 진단 — 자산은 많은데 서로 모른다

지금 구조에서 각 사이트는 **자기 방문자를 자기 안에서 끝낸다.** 도메인이 4개인데 어느 하나도 다른 셋의 존재를 제대로 알리지 않는다. 결과적으로 세 가지를 동시에 잃고 있다.

| 잃고 있는 것 | 구체적 손실 |
|---|---|
| **전환** | 진단(ax)에서 처방받은 사람이 살 수 있는 상품 페이지로 못 간다 |
| **권위** | troe.kr의 20년 백링크·도메인 신뢰가 신규 자산으로 전혀 흐르지 않는다 |
| **AI 인용** | 같은 주체가 4개 도메인으로 흩어져 있어 AI가 하나의 엔티티로 인식하지 못한다 |

**핵심 통찰**: GEO 시대에 도메인 분산은 SEO보다 훨씬 비싼 대가를 치른다. AI는 "이 주체가 누구인가"를 엔티티 단위로 판단하는데, 지금은 박충효·TROE·AX 진단·GAEO가 서로 다른 넷으로 보인다.

## 3. 실행 아이디어 (우선순위 순)

### ★ IDEA 01 — 엔티티 통합 선언 (Entity Consolidation)

**AI에게 "우리는 하나"라고 명시적으로 알린다.** 통합 작업 중 비용 대비 효과가 가장 크다.

**실행**
1. 5개 도메인 전부에 동일한 `Organization` + `Person` 스키마를 심고, `sameAs` 배열에 **나머지 전부를 상호 나열**
```json
"sameAs": [
  "https://troe.kr", "https://axworks.kr",
  "https://park.allrounder.im", "https://gaeo.allrounder.im",
  "https://github.com/saewookkangboy",
  "https://www.linkedin.com/in/chunghyopark/",
  "https://brunch.co.kr/@saewookkangboy"
]
```
2. 모든 도메인 푸터에 동일한 **사업자 정보 블록** (트로이 656-05-00206 · 대표 박충효 · chunghyo@troe.kr) — NAP 일관성이 엔티티 인식의 기초
3. 각 도메인에 `/llms.txt` 배치 — 사이트 목적과 형제 도메인을 평문으로 선언
4. 위키 성격의 `/about/entity` 페이지를 axworks.kr에 두고 전 도메인이 링크

> park.allrounder.im은 이미 `sameAs`에 6개 URL을 넣어둔 상태다. **이 패턴을 나머지 도메인에 복제하기만 하면 된다.** 이미 절반은 되어 있다.

### IDEA 07 — 콘텐츠 1개 → 5자산 배포 파이프라인

이미 보유한 콘텐츠 제작 시스템(Hermes 파이프라인·다포맷 생산)을 통합 배포에 연결.

```
Agent Catalog 템플릿 1종
   ├─ axworks.kr/journal   장문 가이드 (GEO 최적화)
   ├─ LinkedIn             텍스트 포스트 + 캐러셀
   ├─ Instagram            예외 카드 캐러셀 6장
   ├─ 브런치                에세이형 재구성
   └─ 뉴스레터              「가동 로그」 본문
```
카탈로그 15종 × 5채널 = **75개 콘텐츠 유닛**. 6개월치 발행 계획이 자산 하나에서 나온다.

### IDEA 09 — 통합 뉴스레터 「가동 로그」

알고리즘에 좌우되지 않는 유일한 채널. 4개 도메인의 모든 폼이 **하나의 리스트**로 모이게 한다.

- 진단 완료자 / GAEO 사용자 / 카탈로그 다운로드 / 브런치 구독 → 단일 리스트, 태그로 구분
- 격주 발행. 이번 호에 실제로 가동된 에이전트 1개 해부
- 태그별 분기 발송: 진단 완료자에겐 티어별 다음 단계, GAEO 사용자에겐 AICS 리포트
